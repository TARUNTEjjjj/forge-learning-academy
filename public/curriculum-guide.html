Meet your computer

16 hours

A computer follows instructions stored in files. A file has a name, a location and bytes; a folder groups files. A program is one kind of file, while a process is a running instance of a program. Your editor changes source text; the Python interpreter reads that text and performs its instructions.

F02

Paths and the terminal

16 hours

A terminal is a text interface to a shell. The shell starts programs and tracks a current directory. An absolute path names a location from the filesystem root; a relative path starts at the current directory. On macOS or Linux, pwd shows that location and ls lists entries; in PowerShell, Get-Location and Get-ChildItem serve the same purpose. For example, a Windows path can look like C:\Users\YourName\Documents\learning-lab, while macOS and Linux paths start with /. Use your own actual folder path; YourName is an explanatory placeholder.

Practice cd to enter a folder and cd .. to move to its parent. Put quotation marks around a path containing spaces. Run python3 hello.py on many macOS/Linux installations or py hello.py on Windows; the correct command depends on your installer. Use the version command to identify the interpreter, rather than guessing why a command is missing. On Windows, PowerShell and Git Bash are different shells with different path and activation conventions. Choose one for the first exercise and label your notes with its name.

Commands can read or change files, so understand a command before running it. Begin with listing, moving between directories, making a new directory and printing a file. Learn Ctrl+C to interrupt a foreground program. A path error means the shell cannot find the target at the supplied location; inspect the directory before changing the program.

F03

Input, output and a first useful tool

16 hours

An algorithm maps an allowed input to an output. The computer also needs a representation of each: input() reads text, int() converts suitable text to an integer, and print() writes text. The expression 2 + 3 calculates a number; the text "2" + "3" joins characters. Types describe which operations are meaningful.

Build a study-time calculator: read minutes studied, convert to hours and minutes using integer division and remainder, and display a clear result. For a nonnegative integer m, m = 60q + r with 0 ≤ r < 60. This mathematical identity is also an executable check of the program behavior.

For a friendly local application, an input prompt is useful. For a competitive-programming judge, print only the specified output: extra friendly messages can make an otherwise correct answer fail. Keep the calculation in a function so a user interface and a judge-style interface can both reuse it.

PYTHON · WORKED EXAMPLE
def split_minutes(minutes):
    if minutes < 0:
        raise ValueError("Minutes must be nonnegative")
    return minutes // 60, minutes % 60

hours, minutes = split_minutes(125)
print(hours, minutes)

The function returns two values. For 125 minutes, the output is 2 5; verify the quotient-and-remainder identity.

Debugging as an experiment

16 hours

Debugging is a controlled experiment. First describe what you expected, what actually happened and the smallest input that shows the difference. A traceback identifies a sequence of calls and an error location. Read the final error description, then inspect the relevant lines and values; the first visible symptom is not always the original cause.

A program may fail before it runs, stop during execution, or finish with the wrong result. These require different investigations. Treat a repair as unfinished until you rerun the failing example and one previously working example. Record why the change solves the cause. If you ask for help, provide the exact command, the small input, the error and what you tried; remove passwords and personal data from the report.

P02

Loops, functions and decomposition

32 hours

A loop performs a step repeatedly while changing state. Explain a loop with three parts: an invariant, a progress measure and a stopping condition. For summing n values, the partial sum after k iterations should equal the sum of the first k values. This is induction expressed as a program structure.

A function names a reusable operation and exposes inputs and outputs. Prefer returning a value over printing from every helper, because returned values can be composed and tested. Local variables belong to one call. Avoid mutable global state while learning; it hides the relationship between an input and a result.

Build a budget analyzer that accepts a list of daily practice minutes and calculates total, longest session and count above a threshold. Start with simple loops, then compare with standard-library operations. Explain what happens for an empty list instead of relying on a convenient sample.

PYTHON · WORKED EXAMPLE
def total_minutes(sessions):
    total = 0
    for minutes in sessions:
        total += minutes
    return total

assert total_minutes([10, 20, 5]) == 35
assert total_minutes([]) == 0

After k iterations, total equals the sum of the first k sessions. That invariant also covers an empty list.

P03

Collections and representation

32 hours

A list preserves order and permits repeated values. A tuple is useful for a fixed record, a set expresses membership without duplicates, and a dictionary maps keys to values. Choose a representation from the operations your program needs. A mathematical relation is not automatically best represented by a two-dimensional list.

Mutability matters: two names may refer to the same list, so changing it through one name can affect the other. Build tiny experiments with copying, nested lists and function arguments. Strings are immutable; constructing a long result character by character may allocate repeatedly, while collecting parts and joining can be clearer and faster.

Model a learning library as records keyed by problem ID, with a set of tags and a list of attempts. Specify how duplicate IDs and missing fields behave. Keep a distinction between absent data, an empty collection and a real value of zero. Those states often require different application behavior.

PYTHON · WORKED EXAMPLE
attempts = ["graph", "dp", "graph"]
counts = {}
for topic in attempts:
    counts[topic] = counts.get(topic, 0) + 1
print(counts)

A dictionary stores one count per distinct topic. Contrast this with a set, which would keep only membership.

Files, exceptions and modules

32 hours

A process loses its ordinary in-memory values when it exits, so persist the notebook in a file. JSON represents strings, numbers, Booleans, lists, objects and null. Serialize a deliberate data structure instead of arbitrary executable code. Validate a loaded record before treating it as trusted application state.

Use a context manager to close files reliably. Catch the specific failures your application can recover from, such as a missing file on the first run or invalid JSON. Do not catch every exception and pretend the operation succeeded. Separate reading a file, validating data and computing a summary so each failure has a clear owner.

A module is a Python file that can expose functions to other code. Split storage from business rules and command handling. Add an entry point guarded by if __name__ == "__main__" so importing the module does not unexpectedly request keyboard input. Save to a temporary file and replace the old file when appropriate to avoid partial writes.

Tests, types and a small release

32 hours

A test is an executable example of required behavior. Arrange an input, call the operation and compare with an independently chosen expected result. Tests are strongest when they would fail for a plausible bug. Testing an implementation against a second copy of the same mistake gives false confidence.

Type annotations communicate intended shapes and help tools detect mismatches, but ordinary Python does not automatically enforce every annotation at runtime. G01

Snapshots and the three working areas

24 hours

Git records project history on your computer. GitHub hosts repositories and collaboration tools online. They are related but different: you can commit with Git while offline, and a local commit is not automatically uploaded. A repository contains project history; a commit records a snapshot with metadata and parent links. Install Git from the official installation instructions for your operating system and verify git --version in a new terminal before beginning. Git author name and email label commits; they are not a GitHub password or an authentication method.

Your working tree contains the files you edit. The index, often called the staging area, describes the next snapshot. The current commit is the saved baseline. Use git status, git diff and git diff --staged to inspect these views. git add selects content for the next commit; git commit records the staged snapshot.

Initialize a repository for your notebook and configure your author identity. Write .gitignore rules for temporary files, caches and the virtual environment before adding everything. Make one coherent change per commit and explain its purpose. An ignored file already tracked by Git remains tracked until you intentionally remove it from tracking. Inside this repository, set git config user.name "Your chosen author name" and git config user.email "your chosen commit email". Replace the explanatory text with your choices; GitHub offers a noreply commit email if you prefer to keep a personal address private. These commands configure only the current repository.

G02

Branches, merges and conflicts

24 hours

A branch is a movable name for a commit. A commit can refer to one or more parents, producing a directed acyclic graph. Creating a branch is inexpensive because it adds a reference, not a full copy of the project. HEAD usually identifies the branch currently checked out; a detached HEAD points directly to a commit.

Create a feature branch with git switch -c and implement one improvement. Merge combines histories; when branches changed incompatible parts of a file, Git needs you to choose the intended combined content. Conflict markers identify alternatives, but resolving a conflict requires understanding behavior, not merely deleting markers.

Build a deliberate conflict in a practice repository, inspect both branches and the common ancestor, and decide which behavior must remain. Run tests after resolving it. A merge can be textually clean and still introduce a logical bug, so passing conflict resolution is not the same as proving the feature correct.

git log --oneline --graph --all

The first command creates and selects a branch. The second displays history; make and commit a small feature before returning to the original branch.

G04

Recovering and investigating history

24 hours

History is a debugging tool. git log --oneline --graph shows ancestry, git show explains one commit and git blame identifies commits that last changed lines. Blame is a navigation aid, not a judgment about people. Use git bisect in a disposable exercise to find the first bad commit by repeatedly classifying versions.

Different recovery commands act on different objects. git restore can replace working content, git revert creates a new inverse commit, and git reset can move a branch reference and possibly change the index or files. Inspect status, preserve uncommitted work and choose the command from the intended effect. Do not experiment with destructive reset modes on valuable work.

Rebasing replays changes onto a different base and creates new commit identities. It can clarify a private branch, but rewriting shared history can disrupt collaborators. Practice interactive rebase, cherry-pick, stash and reflog in a throwaway repository. Reflog is local recovery information with retention limits; it is not a substitute for backups. During a practice rebase conflict, inspect git status, edit the conflicted file to the intended content, stage the resolution with git add and run git rebase --continue. Use git rebase --abort to return to the pre-rebase state when you want to abandon that rebase. Do not use --skip merely to hide a conflict; it omits a change. Commit objects refer to tree snapshots and parents; refs and reflog explain which commits names currently or previously identified.

D01

Cost models and brute-force oracles

46 hours

Correctness and efficiency answer different questions. Start by specifying what the result means, then construct the simplest correct algorithm. Count dominant operations as input size grows. Big-O is an asymptotic upper bound under a stated cost model; it is not an exact runtime prediction or a promise that two implementations perform equally.

For a list of n values, a single scan uses O(n) inspections, while examining every unordered pair uses O(n²). Python integers can grow beyond a machine word, so arithmetic on arbitrarily large integers is not always constant time. Also account for memory: an n by n table may be impossible even when the recurrence is simple. Distinguish worst-case from expected and amortized bounds: amortized analysis bounds the cost of a sequence, while an expected bound uses an explicit probability model. The input distribution in a benchmark is another assumption and need not match either bound.

Keep the slow correct version as an oracle for tiny random inputs. Compare an optimized version against it and save any disagreement as a regression case. Benchmark separately on representative larger inputs. A timing experiment can expose a practical issue, while a complexity argument explains how the work scales.

D02

Arrays, prefix sums and hashing

46 hours

An array supports efficient indexed access; it does not make every operation cheap. Inserting at the front of a Python list shifts later elements. A prefix sum stores cumulative totals so the sum on a half-open interval [l,r) is prefix[r] - prefix[l]. Define the empty prefix as zero to remove a special case at the left edge.

A hash table supports expected efficient key lookup under its implementation assumptions. Equality and hashing must agree for keys. A set is a natural representation for membership, while a dictionary can accumulate counts. A hash collision does not make two unequal keys identical: a correct implementation also checks equality.

Use prefix sums for many immutable range queries and a dictionary for sparse frequencies. Ask whether values can change after preprocessing, whether negative values occur and whether order matters. These questions determine which shortcut is valid. For example, a sliding-window strategy based on increasing sums may fail with negative numbers.

PYTHON · WORKED EXAMPLE
def prefix_sums(values):
    prefix = [0]
    for value in values:
        prefix.append(prefix[-1] + value)
    return prefix

p = prefix_sums([3, 1, 4, 2])
assert p[3] - p[1] == 5

The final assertion sums the half-open interval [1, 3): the values 1 and 4.

D03

Sorting and binary search

46 hours

Sorting changes a problem by exposing order. A stable sort preserves the input order of equal-key elements, which matters when multiple rankings are combined. State the comparison rule explicitly; a comparator that contradicts itself can invalidate an algorithm. Sorting is often an O(n log n) preprocessing step that enables simpler scans.

Binary search is a proof about a monotone predicate. Maintain a region known to be false, a region known to be true and an unresolved interval that strictly shrinks. Searching for the first value that satisfies a condition is more general than searching for an exact array element.

Apply binary search to the smallest daily capacity that completes a set of study sessions within a deadline. First prove that increasing capacity cannot turn a feasible schedule into an infeasible one. Test the feasibility function independently, then test empty, singleton, all-false and all-true boundary patterns. Never copy a template without its interval invariant.

PYTHON · WORKED EXAMPLE
def first_at_least(values, target):
    left, right = 0, len(values)
    while left < right:
        middle = (left + right) // 2
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle
    return left

Precondition: values is sorted in nondecreasing order. The result can equal len(values), meaning no element is large enough.

D04

Stacks, queues, heaps and two pointers

46 hours

A stack processes the most recently added item first; a queue processes the oldest. These are policies for ordering work. Use a deque for repeated removals at the front in Python. A heap keeps an extreme element available without maintaining a fully sorted sequence; it fits a stream of next-best choices.

Two-pointer and sliding-window techniques reuse work as boundaries move. Prove that each pointer advances at most n times and that the maintained state matches the current window. from collections import deque

def distances(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        vertex = queue.popleft()
        for neighbor in graph.get(vertex, []):
            if neighbor not in distance:
                distance[neighbor] = distance[vertex] + 1
                queue.append(neighbor)
    return distance

PYTHON · WORKED EXAMPLE
def min_sessions(total, sizes):
    unreachable = total + 1
    best = [0] + [unreachable] * total
    for amount in range(1, total + 1):
        for size in sizes:
            if 0 < size <= amount:

    return None if best[total] == unreachable else best[total]

44 hours

A benchmark is a measurement instrument. Define the capability it is intended to measure and collect tasks that represent that capability. Include clear expected behavior and sufficient environment information. If tasks accidentally reveal their own answers, scores may measure leakage rather than skill.

Separate a development set used to refine the evaluator from an unseen evaluation set. Track sources and permissions for task content. Original tasks and licensed datasets are preferable to copying restricted interview or contest material. What this guide establishes

The curriculum has 10 phases, 50 modules and exactly 2,000 allocated hours. Every module contains original instruction, a practical task, observable readiness criteria, an artifact and official resources. Prerequisites form an ordered graph.

Reproducible content checks validate hour totals, structure, source-domain restrictions and problem links. All 12 Python examples parse; behavioral checks cover their examples and core algorithms with deterministic boundary and differential tests. The four shell snippets are parsed without executing their commands. The C++ example is compiled with warnings treated as errors and its output is checked.

The Hypothesis example’s property body is independently exercised using the standard library; this does not certify an installed Hypothesis environment. Link checks validate URL structure and intended providers, not perpetual availability of every external page.

Scope matters. The guide is a curriculum and assessment plan. It does not claim that every external exercise has an integrated judge, that every future project is already implemented, or that a completion checkbox proves mastery. Public deployment, credentialed GitHub writes, large-scale capacity and independent security review require their own verified implementation evidence.

Use varied project behavior to choose the next practice task. A failed run is evidence about the next useful example, never a judgment about intelligence. Keep internal adaptation separate from a public leaderboard, and let learners inspect or delete their learning data.
